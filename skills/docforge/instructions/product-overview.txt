# Product Overview Instruction Template

## Purpose
Describe what the system does from the business perspective.

## Target Audience
Business stakeholders, product owners, engineers onboarding

## Required Sections
1. Core business domains - what business areas does this system cover
2. Key capabilities - major features and what they enable
3. User-visible features - feature list users interact with

## Data Requirements
- Domain graph (REQUIRED - hard gate, no fallback)
- Knowledge graph (for architecture context)

## Depth Level
L1 - Business overview, no implementation

## Template Structure
- Lead with 1-2 sentence summary of what this system is to business
- Organize capabilities by domain (domains come from domain graph)
- For each domain: what problem it solves, what capabilities enable it
- List features users see/interact with
- Keep business language, minimal technical jargon
- Use business terminology from domain graph, not code terminology

## Provenance Requirements
- Tag each capability with domain graph nodes
- Reference which modules implement each capability (at module level, not file level)
- Record git blob hashes of core business logic implementing capabilities

## Common Pitfalls
- Don't describe implementation - describe business capability
- Don't assume technical knowledge of readers
- Don't duplicate flow content - flows show *how*, overview shows *what*
- Don't list every single feature - group by domain and highlight key ones
- Don't use internal code names - use business names

## Notes
- This is business narrative, not a feature matrix
- Cross-reference product/capabilities.md for detailed feature catalog
- If audience-specific overlays exist (product-owner/), reference them
